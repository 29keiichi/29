# 設計書：Googleカレンダー連動「空き枠」表示と自動開閉

作成日：2026-10-26
状態：**設計のみ。まだ開発しない。** 着手するときはこの設計書に沿って実装し、GitHub（リポジトリ「29」）へ公開する。

---

## 1. やりたいこと（目的）

1. ホームページの予約フォームに、**Googleカレンダーで「空き」にした枠だけ**を「予約できる日・時間」として載せる。
2. 空き枠の指定は、店長が Muse（AI）に伝える → Muse が Googleカレンダーに登録する。店長が自分でカレンダーに入れてもよい。
3. 他のポータルサイトや「ありがとうエアコン」など他社から受けた案件を、店長が Googleカレンダーに手動で入れたら、**その枠はホームページ側でも自動で閉じる**（予約できなくなる）。
4. キャンセルなどで予定が消えたら、**その枠は自動でまた開く**。
5. ホームページから予約が入ったら、その枠をすぐ仮押さえして、二重予約（ダブルブッキング）を防ぐ。

## 2. いちばん大事な考え方

- **「空き枠の正本」は Googleカレンダー1つだけ**にする。ホームページはカレンダーを読んで表示するだけ。台帳（スプレッドシート）は今まで通り「予約の記録」専用。
- カレンダーに予定を入れる・消すのは、誰が・どの経路でもよい（Muse／店長手動／他社案件）。ホームページの表示は、毎回カレンダーの最新状態から計算するので、**手作業の同期は一切いらない**。
- ホームページに外へ見せるのは「空いている／埋まっている」だけ。**予定のタイトルや内容（お客さま名・他社名など）は絶対に外に出さない**。

## 3. カレンダーの運用ルール（設計の核）

Googleカレンダーに、イチロー専用のカレンダー **「イチロー空き枠」** を1つ作る。

| 予定の種類 | 入れる人 | 意味 |
|---|---|---|
| 「受付可」の予定 | 店長 or Muse | この時間帯は予約を受け付ける（＝ホームページに空き枠として出す） |
| ふつうの予定（案件・私用など何でも） | 店長（他社案件・ポータル案件を含む） or Muse | この時間帯は埋まっている（＝ホームページでは閉じる） |
| 「仮予約」「確定」の予定 | システム（GAS）が自動作成 | ホームページからの予約で埋まった枠 |

- 時間の区切りは、今の予約フォームと同じ **1日4枠**：9:00〜12:00／12:00〜15:00／15:00〜18:00／18:00〜21:00。
- **空き枠の計算**： 「受付可」の枠のうち、その時間に重なる「埋まっている予定」が1つも無いものだけを、ホームページで予約可能にする。
- 「受付可」を入れていない日・枠は、ホームページには出ない（**開けたい枠だけ開ける**方式。店長が開け忘れたら出ない代わりに、勝手に予約が入る事故がない）。
- 原則 **1枠＝1件**（移動時間と作業時間を見込んで、枠をまたぐ二重受けはしない）。

## 4. 仕組みの流れ

```

店長 →（口頭/チャットで Muse へ「来週の月・水の午前を開けて」）
Muse → Googleカレンダー「イチロー空き枠」に「受付可」を登録


お客さま → 予約ページを開く
予約ページ → GAS（今の予約受付の仕組み）に「空き枠を教えて」と問い合わせ
GAS → Googleカレンダーを読んで「空いている枠」だけを返す
お客さま → 空いている枠の中から選んで送信
GAS → 台帳に記録 ＋ メール送信（今と同じ）＋ カレンダーに「仮予約」を自動作成
→ その瞬間から、その枠は他の人に閉じる


店長 → Googleカレンダーに予定を入れる（いつもの操作）
→ 次にお客さまが予約ページを開いたとき、その枠はもう閉じている


店長 or Muse → カレンダーの予定を消す（または予約をキャンセル扱いにする）
→ 次に予約ページが読んだとき、その枠は自動でまた開いている
```

## 5. 技術の組み立て（今ある仕組みの延長で作る）

新しいサービスは契約しない。今ある部品だけで作る。

- **GAS（既存の「エアコンクリーニングイチロー予約受付」を拡張）**
- 空き枠の問い合わせ窓口を追加：予約ページからの問い合わせに、カレンダーを読んで「空き枠一覧（JSON）」を返す。
- 予約送信の処理に、カレンダーへの「仮予約」自動作成と、送信直前の空き再チェック（二重予約防止のロック付き）を追加。
- 読み取り結果は短時間（数分）キャッシュして高速化。ただし予約送信の直前チェックは必ず最新を読む。
- **ホームページ（yoyaku.html を改修）**
- 日付と時間帯の入力を「空き枠だけが選べるカレンダー形式」に変える。希望は最大3つまで今まで通り選べる。
- 空き枠が取れなかった場合に備え、今の「希望日を自由に書く方式」＋電話相談への案内を予備として残す（仕組みが止まっても予約がゼロにならないように）。
- **Muse（運用担当）**
- 店長の言葉から「受付可」の登録、「埋まった予定」の登録、キャンセルの反映を行う（Googleカレンダー連携は接続済み）。
- 将来：前日に「明日の空き枠」を店長へ知らせる、などの補助も可能。
- **公開範囲**
- 空き枠の公開は「今日から60日先まで」など範囲を決める（要相談事項を参照）。

## 6. 気をつける点（先に決めておくこと）

1. **予約の締切**：当日の枠をいつまで受けるか（例：前日の21時まで／当日の枠は電話のみ）。決めないと直前の予約に対応しきれない。
2. **仮予約の確定方法**：ホームページ予約＝即「仮予約」。店長が内容を見て「確定」にする運用（今のメール確認と同じ流れ）。確定しなかった仮予約は、一定時間で自動で枠を解放するかどうか。
3. **「受付可」の入れ忘れ対策**：開け忘れると予約が入らない。週の初めに Muse が「今週の受付可はこれでいいですか」と確認する運用を推奨。
4. **キャンセルの扱い**：カレンダーの予定を「消す」だけで枠が開く運用にする（台帳側の状態変更もあわせて行う手順を決める）。
5. **二重予約の競合**：2人が同じ枠をほぼ同時に送信した場合、GAS側で先着1件だけを受け付け、後の人には「埋まってしまいました＋近い空き枠」を案内する。
6. **プライバシー**：ホームページに出すのは空き／満だけ。他社案件名・お客さま名はカレンダー内部だけに置き、公開データに混ぜない。
7. **止まったときの逃げ道**：カレンダーやGASが読めないときは、エラーページにせず「自由入力の希望日＋電話案内」に自動で切り替える。
8. **時間の基準**：すべて日本時間（Asia/Tokyo）で固定。海外からのアクセスでもずれないようにする。

## 7. 店長に確認したいこと（開発前に決める）

1. 予約の締切はいつにするか（前日21時？ 当日◯時？）
2. 空き枠を公開する範囲（30日先まで？ 60日先まで？）
3. 1枠＝1件でよいか（同じ枠に2件入れたい日があるか）
4. ホームページ予約は「仮予約→店長が確定」でよいか
5. 「受付可」の登録は、毎週まとめて Muse に頼む形でよいか
6. 他社案件（ポータル・ありがとうエアコン等）も、全部このカレンダーに入れる運用でよいか
